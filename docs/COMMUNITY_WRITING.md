# 스르륵 질문·이용팁 글 작성 지침

## 요청과 결과
“지금 업데이트”, “지금 커뮤 글 작성해줘”는 사용자의 명령으로 시작하여 작성·개선부터 실제 공개 게시와 운영 확인까지 완료하라는 뜻이다. “수동”은 사용자 요청으로 시작한다는 의미이며 사용자가 직접 업로드한다는 뜻이 아니다. 사용자가 초안만 요청한 경우를 제외하고 게시 허락을 반복 요청하지 않는다. 게시판은 질문·이용팁, 목록 주소는 https://ssrrr.net/community 이다. 로그인 후 글쓰기에서 게시판을 선택하고 제목·본문을 붙여 넣어 등록한다.

결과에는 1) 게시판과 세부 주제, 2) 제목과 복사 가능한 본문, 3) 해결하는 질문 한 가지, 4) 연결할 기존 글의 실제 URL과 삽입 위치, 5) 추가 확인할 기능·사실을 포함한다. 운영 메모와 확인 사항은 게시 본문과 분리한다. 확인되지 않은 링크는 만들지 말고 미확인으로 표시한다.

## 주제 선정
검색 실적 CSV가 제공되면 노출은 많고 클릭이 적은 검색어부터 검토한다. 검색 실적 자동 연동은 없다. 데이터가 없으면 실제 반복 질문, 사용자 문의, 확인 가능한 사이트 기능에 근거한다. 검색량·순위·인기도·사용 경험을 지어내지 않는다. 기존 글을 조회하고 같은 질문에 답하는 글이 있으면 중복 신작보다 보완안을 우선한다. 조회가 불가능하면 기존 글 중복 확인이 필요하다고 표시한다.

## 본문
구체적인 상황을 드러내는 제목 → 첫 문단의 답 → 준비 조건과 실행 순서 → 안 되는 환경·권한·브라우저 조건과 대안 → 관련 안내 → 직접 이용 가능한 위치 순서로 쓴다. 독자가 링크를 누르지 않아도 핵심 해결 방법을 알 수 있게 한다. 실제 확인한 기능만 설명하며 반복, 키워드 나열, 가짜 후기를 금지한다. 스르륵과 관계없는 다른 서비스의 기능을 그대로 옮겨 설명하지 않는다.

## 연결
관련 있는 기존 글 URL은 유지한다. 새 글에서 관련 기존 글로 연결하고, 수정 가능한 기존 글에도 새 글의 확정된 공개 URL을 필요한 위치에 추가한다. 기존 본문과 URL은 보존하고 관련 없는 글은 수정하지 않는다. 초안만 요청받은 경우에는 연결 위치를 제안만 한다. 링크 문구는 목적을 구체적으로 설명한다. 편집기는 URL 붙여넣기를 지원하므로 설명 문장 다음 줄에 실제 URL을 둔다.
세부 주제는 자유 입력(40자 이내)이며 정확히 같은 게시판·세부 주제의 공개 글 최대 4개가 상세 페이지에서 자동 연결된다. 의미가 다른 글을 연결하려고 같은 주제명을 쓰지 않는다. 주제가 없는 과거 글에는 관련성이 추정된 자동 링크를 만들지 않는다. 기존 본문을 일괄 변경하지 않는다.

## 외부 커뮤니티
해당 게시판의 관심사와 규칙에 맞추고 운영자 관계를 밝힌다. 동일 홍보 문구를 여러 곳에 복제하지 않는다. 외부 링크를 남긴 것만으로 검색 순위가 오른다고 주장하지 않는다.

## 발행 후
실제 질문 해결 반응, 반복 질문, 링크 클릭과 이용 전환을 확인 가능한 데이터로 평가한다. 현재 별도의 클릭·전환 추적이나 검색 실적 자동 분석은 구현되지 않았다. 잘못된 내용은 기존 글을 수정하고 비슷한 글을 양산하지 않는다.

## 완료 절차
게시 전 현재 공개 목록을 확인해 중복을 방지한다. 기존 안전한 관리자 글쓰기·수정 경로를 사용한다. DB 기반 게시글은 저장 즉시 반영되므로 별도 코드 배포가 필요하지 않다. 운영 문서나 코드가 바뀌면 관련 파일만 커밋·Git push하고, 런타임 코드가 바뀐 경우 검증 후 운영 배포한다. 강제 push 금지, 기존 무관한 변경 보존. 공개 URL에서 제목·본문·양방향 링크와 중복 여부를 확인하고 실제 게시/배포 여부, 커밋, 남은 조치를 보고한다. 유료 API·무인 예약 자동화·외부 커뮤니티 게시를 추가하지 않는다. 인증·권한 등 실제 장애만 구체적으로 보고한다.
