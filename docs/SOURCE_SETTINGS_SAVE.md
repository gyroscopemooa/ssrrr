# 수집 설정 저장 개선 (2026-09-22)

## 원인
설정 편집기를 열 때 requiredFields/optionalFields/listSelectors/customStages의 표시용 기본값을 실제 편집 상태에 주입했다. 이전 설정에 이 필드가 없으면 게시 개수만 변경해도 sourceIdentity가 달라져 OFF/재검사가 필요했다.

## 수정
- 표시용 기본값을 렌더 단계에서만 제공한다. 실제로 변경한 필드만 기존 설정에 반영한다.
- 하루 게시 수, 스캔 수, 간격, 인기 점수/최소 기준 등은 기존 검증 및 ON 상태를 유지한다.
- 주소/추출 규칙/수집 방식/필수 데이터/댓글·미디어 조건 변경은 저장 후 자동 검사한다.
- ON을 선택한 설정은 검사 동안 OFF, 동일 저장 요청의 유효한 PASS에서만 자동 ON 복귀한다. 실패하면 OFF다.
- 새 저장은 이전 검사 작업을 취소한다. 검사 중 명시적으로 OFF 저장하면 자동 복귀 의도도 취소한다.
- 오래된 작업의 완료/실패 및 다른 주소의 검증 결과로 새 설정을 켜지 않는다.
- 수집 중 스캔 한도를 낮춰도 반환 항목 초과 때문에 소스를 실패시키지 않고 현재 한도로 제한한다.
- DB migration, dependency 추가 없음. 기존 검증 identity 형식/기본 소스 감사 결과 유지.

## 확인
- 전체 로컬 단위 테스트 55개 통과 (보류 중인 LIVE-SUB 테스트 16개 포함).
- typecheck 통과, 변경 파일 lint 오류/경고 0, build 통과.
- 격리 DB/API 회귀 통과: 일반 기능 및 일일 한도 변경, URL 자동 검사, 성공 ON 복귀, 실패 OFF, 명시적 OFF 우선, 이전 작업 무효화.
- 실제 외부 사이트 신규 수집 검사를 운영 데이터에 임의 실행하지 않음. 검사 실행에는 연결된 worker 필요.
- 하루 한도 변경은 이후 후보 선택/예약에 적용된다. 기존 예약을 취소하거나 재배치하지 않는다.
- 브라우저 클릭 QA는 이번 요청 범위에서 실행하지 않음.

## 배포 분리
LIVE-SUB 이벤트 연결은 아직 배포하지 않는다. 이번 수집 설정 수정만 커밋한 별도 체크아웃에서 운영 배포본을 빌드한다.
