# 수집 본문 품질 수정 — 2026-09-22

## 확인한 원인과 수정
- 엠봉: 쉼표로 나열한 CSS 선택자는 우선순위가 아니라 DOM 순서로 반환되어, 본문 `.xe_content`보다 바깥 `article`을 선택했다. 본문 요소를 우선 선택하고 복제한 DOM에서 댓글·조작 요소를 제거한다. 별도 댓글 추출용 원본 DOM은 보존한다.
- 엠봉 조회/추천/댓글 수: 기존 공통 선택자로 0이 되어 점수 산정이 무의미했다. 실제 표의 열과 `.cmt_num`으로 수정했다. 저장된 구형 기본 선택자도 처리하며 사용자가 정한 다른 선택자는 덮어쓰지 않는다.
- 김채현: 인벤 원본에 video 10개, image 1개, zero-width spacer가 있었다. 저장된 글에는 이미지 1개만 있다. 파서와 화면에서 빈 문단을 제거한다. AUTO의 최소 요청 정책 및 사용자 영상 설정은 유지한다. 영상을 선택적으로 가져오려면 DETAIL_NO_COMMENTS + videos ON, 댓글도 수집하려면 FULL + commentLimit > 0으로 재검사/재수집해야 한다. 이번 변경으로 기존 글의 영상 10개를 복구한 것은 아니다.
- 이연복: 원본 https://theqoo.net/hot/4352319280 에 이미지 3개와 https://img.theqoo.net/EaYlKp 링크가 따로 존재한다. 저장된 이미지도 3개다. 이 링크를 실패 이미지로 단정하거나 삭제하지 않는다.
- 군 상관 글: 저장된 본문에 뉴스 링크가 있으며 파서에는 해당 뉴스 링크를 임의로 생성하는 코드가 없다. 원문 상세 URL을 확보하지 못했으므로 원문과 직접 대조 완료로 보고하지 않는다.
- 목록 요약에서는 단독 URL/출처 줄을 제외한다. 상세 본문과 원문 링크는 유지한다.
- 기존 댓글 저장 경로는 우리 comments 테이블로 분리되어 있었다. API와 화면에 imported origin을 전달하여 `원문 댓글`로 표시한다. 자동 모드에서는 필수 댓글로 지정하지 않으면 별도 댓글 수집을 생략한다. 사용자 댓글 설정은 일괄 변경하지 않았다.

## 기존 글 복구
`0003_repair_mbong_import.sql`은 확인한 엠봉 게시글 1건만 대상으로 한다. id/system author/원본 body 전체가 일치해야 적용된다. job_events의 content_repair_backup에 수정 전 body/thumbnail을 저장하고, 원본 이미지 1장과 본문만 남긴다. 다른 글, 댓글, 첨부 파일, 추천, 조회 수는 삭제하지 않는다. 새 DB에서는 no-op. 재실행 및 검사 이후 편집된 본문 보호를 SQLite에서 확인했다.

## 검증
- 단위/회귀 테스트 38개 통과 (새 품질 테스트 6개 포함).
- 실제 엠봉 목록 전체 20개, 상세 1개, 이미지 1개 PASS. AUTO이므로 별도 댓글 요청은 없음.
- 문제의 엠봉 원문 HTML 재파싱: 본문 이미지 1개 + 텍스트, 별도 댓글 3개. 수정/삭제/광고/프로필 이미지는 본문에서 제외.
- 인벤 원문 HTML 재파싱: video 10개 + image 1개, 빈 text 0개. 영상 다운로드 10개 성공을 뜻하지 않음.
- 타입 검사/빌드 성공. 변경 파일 lint 오류 0, 기존 경고 5.
- 격리된 로컬 DB API 회귀 테스트 통과: 회원/포인트/다운로드/인기글, 수집/예약/댓글 분리 및 origin, Gmail/경제글, 쇼츠 권한 및 취소 등.
- 운영 사이트 UI는 PC 계정 접근 제한으로 브라우저 육안 재검수를 하지 않았다. 배포 이후 API로 본문 복구 결과를 재확인한다.

## 선정 기준의 한계
원본의 best/hot 게시판이라도 유머만 있는 것은 아니다. 기본 인벤 주소는 일반 오픈이슈 목록이다. 점수는 추천×가중치 + 댓글×가중치 + 조회×가중치이며 재미를 평가하지 않는다. 보관 기간은 최초 수집 시각 기준이다. 이 변경에서 모든 소스를 인기 전용으로 바꾸거나 운영 필터 임계값을 임의로 변경하지 않았다.
